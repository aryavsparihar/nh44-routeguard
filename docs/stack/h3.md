# H3 hexagons

**In one line:** H3 splits the map into equal hexagons, so we can give each small stretch of road its own risk colour.

## What it is

H3 is a free system from Uber that covers the whole Earth in hexagons. Each hexagon has an id (like `8828308281fffff`). "Resolution" picks the size: a higher number means smaller hexagons.

## Why we use it

- A zone is long (tens of km). Hexagons show which part of the zone is the problem.
- Every hexagon is about the same size, so they are easy to compare.
- The same library exists for Python (risk job) and JavaScript (app), and both give the same ids.

## Where it is in our project

| Path | What it holds |
| --- | --- |
| `jobs/tools/build_hexes.py` | Finds every resolution-8 cell (about 0.8 km² at this latitude) that the NH-44 driving line passes through |
| `jobs/load_hexes.py` | Loads those cells into the database |
| `jobs/risk/hexes.py` | Scores each hexagon in the hourly job |
| `src/server/risk/hexes.ts` | Turns each id into its outline with `cellToBoundary` for the map |
| `app/api/v1/risk/hexes/route.ts` | `GET /api/v1/risk/hexes?horizon=0\|12\|24\|48` |
| `src/ui/risk/HexCard.tsx` | The card shown when you tap a hexagon |

Libraries: `h3` 4.5.0 in Python, `h3-js` 4.5 in the app.

## Questions you may be asked

**Q: Why hexagons and not squares?**
A: Every neighbour of a hexagon is the same distance away, and hexagons follow a winding mountain road more evenly than squares.

**Q: Why resolution 8?**
A: About 0.8 km² per cell: small enough to show a slide-prone stretch, big enough that the map isn't thousands of tiny shapes.

**Q: Does the server send all the hexagon shapes every time?**
A: The API sends the outlines with the scores, and the answer is cached with an ETag like the other risk routes, so a phone that already has it gets a 304.

**Q: Is a hexagon's risk more exact than the zone's?**
A: It uses the nearest weather points, but the weather model's grid is a few km wide. It shows where to look, not an exact spot.
