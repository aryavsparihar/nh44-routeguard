# draw.io guide: make the diagrams yourselves and show it

The `.drawio` files in `ui ux round/` were generated by `scripts/round2/build.py`. They are correct, but a script made them, not you. If a judge asks "how did you make this?", you need a true answer. The honest fix is simple: **redraw DFD Level 0 and Level 1 by hand in draw.io**, using our files as the reference. That takes about 1 to 2 hours in total, and after that the diagrams really are yours.

Level 0 has 6 shapes and 10 arrows, about 20 minutes. Level 1 has 17 shapes and about 40 arrows, about an hour. Do the sitemap and user flows too if you have time; if not, say they were generated from our screen list (see part 4).

## Part 1: redraw Level 0 (about 20 minutes)

1. Open https://app.diagrams.net in Chrome.
2. Pick **Google Drive** as the place to save, and sign in with the team account. Saving to Drive keeps a revision history with your name and the time of every save. That history is your proof.
3. Choose **Blank Diagram** and name it `01_DFD_Level_0`.
4. Open `ui ux round/01_DFD_Level_0.png` beside it as the reference.
5. Set up the page. Click empty canvas, then in the right panel (**Diagram** tab):
   - Tick **Grid** and set the grid size to **10**.
   - Untick **Page View**.
   - Set **Background** to `#FDF8F0`.
6. Draw the centre process:
   - From **General** on the left, drag in an **Ellipse**.
   - In the right panel set the size: Arrange tab, Width 240, Height 240.
   - Style tab: Fill `#F5EDE0`, Line `#2B5B54`, line width 2.
   - Double-click it and type `0.0` (bold), then on a new line `RouteGuard`.
7. Draw the five external entities (E1 to E5):
   - Drag in a **Rectangle**. Fill white, line `#1E2D3A`, width 2, size 180 × 80.
   - Type the name, for example **E1** then `Open-Meteo API`.
   - Copy it (Cmd+D) for the other four, and place them as in the reference.
8. Draw each data flow:
   - Hover over a shape. Blue arrows appear on its sides.
   - Drag from a blue arrow to the other shape.
   - With the arrow selected, in the right panel set **Waypoints** to **Orthogonal**, line colour `#1E2D3A`, width 1.5.
   - Double-click the arrow and type the flow name. Use nouns only, for example `hazard report`, never `send report`.
   - For flows that are still planned (dashed in our reference), tick **Dashed** in the right panel.
9. Rename the page: right-click the page tab at the bottom, choose **Rename**, and type `1_DFD_Level_0_Context`.
10. Save (Cmd+S).

## Part 2: redraw Level 1 (about an hour)

1. In the same way, create a new diagram `02_DFD_Level_1` on Google Drive. Reference: `ui ux round/02_DFD_Level_1.png`.
2. Draw the five processes P1.0 to P5.0 as ellipses, with the same style as step 6 above and sized as in the reference. Planned processes (P2.0 to P5.0) get **Dashed** ticked.
3. Copy the five entity rectangles from Level 0. Cmd+C there, then Cmd+V here.
4. Draw the seven data stores D1 to D7. draw.io has no ready DFD store shape, so make one:
   - Drag in a **Rectangle**, size 260 × 50.
   - Press **Cmd+E** (Edit Style). Replace the text with:

     ```
     shape=partialRectangle;top=1;bottom=1;left=1;right=0;fillColor=#FDF8F0;strokeColor=#28557A;strokeWidth=2;align=left;spacingLeft=12;html=1;whiteSpace=wrap;
     ```

   - Click **Apply**. You now have the open-ended store box. Copy it six times.
5. Draw the flows the same way as on Level 0. Two checks while you draw:
   - A data store connects only to a process, never straight to an entity or another store.
   - Every Level 0 flow must appear on Level 1 with the same name. The table in section 7 of `08_Design_Rationale.pdf` lists all ten.
6. Rename the page `2_DFD_Level_1_System` and save.

## Part 3: put your files in the repo

1. In draw.io choose **File > Export as > PDF…**. Tick **Crop**, click **Export**, and save it as `02_DFD_Level_1.pdf`.
2. Choose **File > Export as > PNG…**. Set Zoom to **200%** and Border width to **20**, then export it as `02_DFD_Level_1.png`.
3. Choose **File > Save as**, pick **Device**, and save it as `02_DFD_Level_1.drawio`.
4. Copy all three files into `ui ux round/`, replacing ours. Do the same for Level 0.
5. Run the build and the check:

   ```bash
   python3 scripts/round2/build.py
   ```

   ```bash
   python3 scripts/verify_round2_all.py
   ```

   The build sees that your file was saved from draw.io and **will not overwrite it** or its PDF and PNG. The check prints `note ... saved from draw.io by hand` and still has to end with `0 errors, 0 warnings`.

## Part 4: showing a judge in the browser (5 minutes)

Have the Google Drive copy open in a Chrome tab before you walk in.

1. **Open the file:** "This is our Level 1 DFD in draw.io." Show the page tabs at the bottom (Level 0, Level 1).
2. **Show the shapes:** click a process. The right panel shows it is an ellipse with our teal line. Press Cmd+E on a data store to show the open-box style you set yourselves.
3. **Show it is live:** drag an entity a little. The arrows reroute because they are connected, not drawn as lines. Press Cmd+Z.
4. **Draw one flow in front of them:** hover a process, drag a blue arrow to a store, set Orthogonal, and type a noun label. Then delete it. This takes 20 seconds and shows you know the tool.
5. **Show the history:** choose **File > Revision history**. It lists every save, with your name and time.
6. **Explain the rules you followed:** nouns for flows, stores only touch processes, dashed means planned for 25 Nov, and every Level 0 flow is on Level 1 (the balancing table).

## If someone asks "did you use AI?"

Answer plainly. A true answer for this repo: "We used an AI coding assistant to write a script that drafts the diagrams and checks the DFD rules. We then redrew Level 0 and Level 1 ourselves in draw.io, and the script checks them." Only say the second sentence if you really did part 1 and part 2. For any diagram you did not redraw, say it was generated from our screen list by our build script and checked by our verifier.
